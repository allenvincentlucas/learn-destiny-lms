Module 3: Patron Management & Class Schedules

SIS imports, class rosters, and the “Currently Teaching” flag — the back-office work that makes circulation work on day one.

Welcome to Module 3: Patron Management & Class Schedules of the Follett Destiny Library Management System (LMS) training program. Building upon system navigation and security configurations established in Modules 1 and 2, this module focuses on student and staff account administration, Student Information System (SIS) data synchronization, and course roster integration (Follett School Solutions, "Manage Patrons").

Accurate patron management and class schedule alignment enable seamless circulation, automated overdue tracking, and efficient bulk resource distribution across classrooms and grade levels (Follett Software, "Back-to-School Readiness").

What You'll Learn

  • Create and configure an individual patron record, including barcode, District ID, and Patron Type.
  • Choose the correct bulk-import method (Direct Web Import, PIC, or Scheduled Update) for a given SIS scenario.
  • Diagnose and resolve at least two common patron-import job errors.
  • Link class schedules to course rosters and explain the purpose of the "Currently Teaching" flag.
  • Apply data-retention rules correctly when inactivating vs. deleting a withdrawn or graduated student record.

2. Patron Management & Roster Synchronization

A. Individual Patron Administration

Librarians manage individual patron records by navigating to Back Office > Manage Patrons (Follett School Solutions, "Manage Patrons"). Key capabilities include:

  • Creating, editing, merging, and archiving student, faculty, and staff profiles (Tech Librarian Helpdesk).
  • Assigning patron barcode numbers, District IDs, graduation years, and homeroom locations (Follett School Solutions, "Import Patron Records").
  • Setting Patron Types (e.g., Student, Teacher, Staff, Administrator) which dictate circulation loan limits, fine rates, and borrowing privileges (Follett School Solutions, "Set Up Patron Types").
  • Enabling the "Currently Teaching" flag on faculty accounts to allow class schedule assignments and textbook transfers (Follett School Solutions, "Class Import Converter").

B. Bulk Patron Imports & SIS Integration

To maintain thousands of student records across a district, Destiny supports bulk demographic imports:

  • 1. Direct Web Import (Back Office > Import Patrons): Uploads CSV or ZIP files (up to 500 MB) directly through the browser interface, with duplicate resolution rules to preserve, merge, or replace existing records (Follett School Solutions, "Import Patron Records").
  • 2. Patron Import Converter (PIC): A standalone utility (PatronImportConverter.exe) that transforms raw CSV exports from any school Student Information System (SIS) into Destiny-compliant XML format, mapping custom fields to standardized patron attributes (Follett School Solutions, "Patron Import Converter").
  • 3. Scheduled Patron Updates (Back Office > Update Patrons > Schedule): Automated daily or weekly background synchronization jobs executed at the district level to automatically add new enrollments, update grade levels, and archive transferred or graduated students (Follett Software, "Schedule a Patron Update").

C. Patron Management 2.0 (Destiny 24.0)

Destiny 24.0 introduces a modernized patron search and details experience for both Library Manager and Resource Manager (Follett Community, "Destiny 24.0 Readiness Kit"):

  • Richer Filters & Recent-Patron Lists: Narrow patron searches with expanded filter options and quickly return to recently viewed patron records (Follett Community, "Destiny 24.0 Readiness Kit").
  • Permission-Aware Views: The patron details screen adapts to the logged-in user's access level, showing only the fields and actions that user's role permits (Follett Community, "Destiny 24.0 Readiness Kit").

3. Class Schedules & Course Section Integration

Integrating class schedules connects learning resources directly to academic courses, teachers, and enrolled students (Follett School Solutions, "Class Import Converter"):

A. Class Schedules Setup (Back Office > Update Classes)

  • Links courses, section numbers, instructional locations, and assigned faculty members (Follett School Solutions, "Class Import Converter").
  • Enables Class Set Checkouts, allowing librarians to check out class sets of textbooks, laptops, or literature kits to an entire course roster in a single transaction (Follett Software, "Back-to-School Readiness").
  • Identifies district-wide textbook shortages or surpluses prior to term launches (Follett School Solutions, "Class Import Converter").

B. Class Import Converter (CIC)

  • Converts SIS schedule CSV exports into XML format for automated upload (Follett School Solutions, "Class Import Converter").
  • Verifies that all course instructors are marked as "Currently Teaching" and associated with the correct school site prior to roster matching (Follett School Solutions, "Class Import Converter").

4. Curated Verified Resources and Video Tutorials

Module 3 Supplement: SIS Integration, Import Error Troubleshooting, Parent Linkage & Data Retention

A. District-Specific SIS Integration Guidance

Destiny integrates with major Student Information Systems (SIS) through automated data pipelines (Admin > Update Patrons > Schedule) (Follett School Solutions, "Add a Scheduled Patron Update"):

  • PowerSchool Integration: Configured via PowerSchool AutoComm / AutoSend scripts that generate nightly CSV exports sent over SFTP to Destiny. Uses the Patron Import Converter (PIC) property map to align PowerSchool Student_Number to Destiny District ID (GitHub, "Import from PowerSchool").
  • Infinite Campus Integration: Utilizes the Infinite Campus Data Extract Utility or native OneRoster API endpoints to stream real-time demographic and course schedule data directly into Destiny without manual flat-file handling (Follett Community, "Feed Detail").
  • Skyward & Aeries Integration: Exports automated CSV roster files over SFTP, mapping Skyward primary guardian emails and student IDs to Destiny patron fields (Aeries Software).

B. Import-Error Troubleshooting & PIC Error Reference

Librarians and system administrators monitor import results in the Job Manager summary log (Admin > Job Manager) (Follett School Solutions, "Common Exceptions"):

  • Header Error: Occurs when an unparsed XML file is manually uploaded via Back Office > Import Patrons instead of district XML upload utilities. Resolution: Convert CSV files using the Patron Import Converter before uploading (Follett School Solutions, "Patron Import Converter").
  • Required Field "District ID" is Blank: Triggered when the district setting "Require District ID for patron records" is active, but incoming CSV rows lack unique student IDs. Resolution: Verify SIS export mappings and confirm student IDs are populated in the source file (Follett School Solutions, "Common Exceptions").
  • Duplicate Barcode / Username Conflict: Occurs when an incoming record matches an active patron with conflicting credentials. Resolution: Set PIC duplicate rules to "Merge incoming records" or resolve barcode exceptions directly in the Job Summary (Follett Software, "Common Exceptions").

C. Parent/Guardian Account Linkage & Automated Email Notices

  • Parent Contact Fields: Patron records store primary and secondary parent/guardian names, phone numbers, and email addresses (Email 1 and Email 2) (Follett Community, "Idea: Parent/Guardian").
  • Automated Overdue Notices: When generating overdue or fine reports (Reports > Library Reports > Current Notices), librarians select "Send via Email" and target Parent/Guardian Email to automatically send email notices to guardians (Thrillshare).
  • Destiny Parent Portal: Enables primary guardians registered in PowerSchool or Skyward to view their child's active loans, due dates, and fine status through a dedicated parent view (Finalsite).

D. Student Data Retention & Graduated Senior Purge Policies

Districts manage student record lifecycles to balance audit requirements with student data privacy laws:

  • Inactivation vs. Deletion:
    • Inactivating: For withdrawn students, setting patron status to "Inactive" (or pre-facing usernames with "Inactive-") revokes borrowing privileges while preserving circulation history and fine records (Follett Software, "Schedule a patron update").
    • Automated Senior Purge: Under Admin > Update Patrons > Schedule, administrators enable "Delete graduated seniors without transactions at the beginning of the new school year". This automatically purges graduated student profiles that have no unreturned items or unpaid fines (Follett Software, "Schedule a patron update").
  • Handling Outstanding Transactions: If "Allow patrons with outstanding transactions to be deleted" is enabled during a purge, any unreturned items are marked "Lost" and open fines are cleared from Destiny (Follett Software, "Schedule a patron update").
  • Historical Checkout Purging: To protect student reading privacy under district retention policies, Destiny automatically purges historical patron reading logs after a district-defined time period (e.g. upon graduation or after 1–3 years) (Follett School Solutions, "Patron Status").

5. Practical Hands-On Learning Activities

To complete Module 3, new librarians should perform the following hands-on exercises in their Destiny sandbox or live site:

  • Activity 3.1 - Manual Patron Account Creation: Navigate to Back Office > Manage Patrons, click Add New Patron, create a new test teacher account with the "Currently Teaching" flag enabled, assign a unique barcode, and set their site association (Tech Librarian Helpdesk; Follett School Solutions, "Class Import Converter").
  • Activity 3.2 - Patron Import Configuration & Job Audit: Navigate to Back Office > Import Patrons, test uploading a sample patron CSV file, select the duplicate matching rule to "Merge incoming records", click Import, and review the resulting Job Summary log for errors (Follett School Solutions, "Import Patron Records").
  • Activity 3.3 - Class Schedule & Roster Inspection: Navigate to Back Office > Update Classes, inspect existing course sections, verify teacher assignments, and practice linking a class set of resources to an active course section (Follett School Solutions, "Class Import Converter").

Q4. Under the automated senior purge, what happens to a graduated student's record if they have unpaid fines?

  • B. It is excluded from the automatic purge unless outstanding-transaction deletion is separately enabled
  • C. It is converted to a Guest account
  • D. It is merged with a sibling's record

Q5. A teacher's roster import keeps failing with a "Duplicate Barcode / Username Conflict." What are two ways to resolve this?

Show key points
Set the PIC duplicate rule to "Merge incoming records," or manually resolve the specific barcode exception directly in the Job Summary log.

Q6. Why does Destiny distinguish between "inactivating" and "deleting" a withdrawn student's account? Give one privacy or audit reason for each.

Show key points
Inactivating preserves circulation history and fine records for audit purposes while revoking borrowing privileges; deleting removes the record, so districts balance audit/financial needs against reading-privacy retention limits (e.g., purging historical checkout logs after 1-3 years).
